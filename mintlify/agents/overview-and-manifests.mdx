Any strategy in Sisera can become a persistent autonomous agent (`/agents` and `@sisera/agent-runtime`) that monitors markets around the clock using the exact same technical, valuation, corroborated event, liquidity, and portfolio intelligence available to a human trader.

---

## Institutional Governance Principles

1. **No Direct Execution:** Agents never execute orders directly against venues. They emit structured trade proposals to the policy evaluator and pre-trade risk engine.
2. **Deterministic Sandboxing:** Strategies execute inside isolated evaluation contexts with hard caps on maximum allocated capital, per-trade notional, open positions, and slippage budget.
3. **Immutable Version Hashing:** Every agent configuration is compiled into a cryptographically hashed manifest. Modifying any parameter (universe, entry/exit rule, stop-loss, or capital limit) produces a **new manifest version** that restarts promotion evaluation from `draft`.

## The Six Autonomy Levels

Operators assign each agent an explicit autonomy disposition (`POST /v1/agents/:id/autonomy`):

| Level | Identifier | Execution Authority | Human Supervision |
| --- | --- | --- | --- |
| **0** | `research` (`RESEARCH`) | Read-only market data and quantitative evaluation. Cannot propose trades. | None |
| **1** | `suggest` (`SUGGEST`) | Generates trade recommendations and signals with full rule rationale. | Operator must manually create and submit the order. |
| **2** | `confirm` (`CONFIRM`) | Compiles structured trade proposals (`GET /v1/agent-orders`); awaits one-tap approval. | Mandatory operator approval (`POST /v1/agent-orders/:id/approve`) per trade. |
| **3** | `policy_auto` (`POLICY_AUTO`) | Automatically executes proposals that strictly satisfy the manifest and risk mandate. | Real-time monitoring; manual pause/kill override (`POST /v1/agents/:id/pause`). |
| **4** | `autonomous` (`AUTONOMOUS`) | Continuous multi-market execution within risk boundaries. | Daily supervision; automated circuit breakers. |
| **5** | `risk_only` (`EMERGENCY_RISK_ONLY`) | Dedicated watchdog mode authorized **only** to reduce exposure or close positions. | Post-incident audit review. |

Agents can be authored via YAML manifests (`AGENTS.md`) or structured JSON payloads (`POST /v1/agents` and `POST /v1/agents/:id/versions`):

## Append-Only Decision Trail

Every 60 seconds, the agent runtime ticks each active agent and writes an immutable decision record to PostgreSQL containing:

- **Observed State:** Exact market prices, Pyth reference premiums, technical indicator values, and active event clusters at tick time.
- **Rule Evaluation Matrix:** Pass/fail status for every entry and exit condition in the manifest.
- **Disposition & Risk Outcome:** Whether the tick resulted in `hold`, `propose_entry`, `propose_exit`, or `blocked_by_risk`, along with full pre-trade risk engine attribution.
- **Agent Book Accounting:** Proposals, fills, realized P&L, and implementation slippage are attributed directly to the agent's isolated book.
